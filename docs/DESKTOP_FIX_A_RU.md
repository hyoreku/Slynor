# Slynor — desktop patch A

Дата: 27 октября 2026 года. Это проверенный на Linux кандидат исходников; Windows-релиз не объявляется.
Основа: OwnPlayerMusic(2).zip, SHA-256 `0466f8f6fda43f9e4b4886f21247bb8bcff45ab65e0c5796decbce0958a7bf77`.
Оригинальный ZIP, его dist и настройки машины не изменялись.

## Что сделано

1. Общая SoundCloud-плашка удалена из шапки. Сведения об источнике текущей песни появляются только
   для реально выбранной SoundCloud-записи с подходящей ссылкой; устаревшие метаданные другой песни не используются.
   Восстановлен отсутствовавший официальный PNG, без изменения его байтов; атрибуция самого SoundCloud-контента сохранена.
   Большая плашка в строке заменена компактным оформлением. Это не удаление провайдера SoundCloud.
2. Пустой контейнер выдачи, канал или плейлист больше не превращаются в песню. Проверяются тип объекта,
   адрес индивидуальной записи и YouTube ID. Проверка есть в worker и при приёме карточек каталогом.
   Короткие/встроенные YouTube-ссылки приводятся к каноническому watch URL; лишние параметры не становятся идентичностью песни.
3. Новые файлы получают читаемое имя «Исполнитель - Название.ext»; совпадения — «… (2).ext» и далее.
   Существующие файлы не затираются. Если исполнитель неизвестен, он не выдумывается.
4. Название, исполнитель и альбом сохраняются для новых загрузок. Поддерживаемые недостающие теги заполняются
   на временной копии без перекодирования аудио; имеющиеся теги сохраняются. При ошибке записи тегов исходная копия не портится.
5. Для сохранения сведений в том числе в WebM/AAC создаётся небольшой соседний файл `.slynor.json`.
   Он содержит текстовые метаданные и каноническую публичную страницу источника, но не media URL, cookies или токены.
   Запись применяется только при совпадении имени, размера и времени изменения аудио. Это проверка актуальности,
   а не криптографическое подтверждение происхождения записи. Длительность каталога не выдаётся за измеренную длительность файла.
6. При явном повторном скачивании из старого кеша добавляются отсутствующие сведения для отображения;
   имя, байты и mtime существующего аудио сохраняются. Старый пользовательский companion-файл не перезаписывается.
   Метаданные библиотеки и текущего плеера обновляются в UI и тогда, когда новая обложка отсутствует.

Массового прохода по старой музыке, переименования, изменения тегов существующих песен и миграции плейлистов нет.
Для старого файла, не выбранного повторно и не имеющего тегов/сохранённых сведений, прежнее отображение может остаться.

## Как применить к Windows-исходникам

Комплект содержит полное чистое дерево `Slynor/`, Git bundle и манифест только изменённых файлов.
dist, .venv, .providers, .search, runtime_paths.json и музыка не включены в комплект и не изменяются помощником.
Не накладывать всё дерево вручную поверх единственной рабочей установки.

1. Закрыть плеер. Проверить резервирование рабочей Windows-версии и пользовательских данных по этапу 0 ТЗ.
   Помощник ниже резервирует только изменяемые исходники; это не backup музыки и плейлистов.
2. Распаковать ZIP отдельно от рабочего проекта и открыть PowerShell в его папке `Slynor`.
3. Выполнить проверку без записи, используя уже существующий Python проекта:

```powershell
$project = 'D:\Projects\ownwork\OwnPlayerMusic'
$python = Join-Path $project '.venv\Scripts\python.exe'
& $python .\APPLY_PATCH_A.py --project $project --check
```

4. Если проверка прошла, применить:

```powershell
& $python .\APPLY_PATCH_A.py --project $project
```

Помощник сначала сверяет исходные и новые SHA-256. При локальных правках он останавливается до записи;
режима принудительного затирания нет. Перед изменением сохраняет прежние файлы в отдельную папку рядом
с проектом: `<имя проекта>-source-backup-<время>-<суффикс>`, выводит точный путь и проверяет хеши копий.
Имена этой папки формируются во время запуска; наличие такой копии на ПК владельца здесь не подтверждено.
Повторное применение уже установленных файлов безопасно: они пропускаются.

Если операции записи прерваны, резервная копия остаётся. После устранения причины можно повторить применение:
уже обновлённые файлы будут пропущены, остальные снова проверены. При ошибке local_changes_preserved нужно
сопоставить локальный файл с патчем; автоматически перезаписывать его нельзя.

Если `.venv\Scripts\python.exe` отсутствует, вместо него для самого помощника подойдёт уже установленный Python 3.13
через `py -3.13`. Сам помощник использует только стандартную библиотеку и ничего не устанавливает.
Работа GUI всё равно требует окружения исходников по README/CONTRIBUTING. Если используется только EXE,
этот комплект сам по себе не меняет код внутри EXE.

5. Запускать обновлённые исходники:

```powershell
Set-Location -LiteralPath $project
.\START.cmd
```

Старый EXE из dist не пересобирался и не является проверкой этого патча.
Python-помощник проверен на Linux с тестовыми деревьями и с исходниками из ZIP. Нативное применение на Windows ещё не проверено.

## Как откатить

Закрыть плеер. Взять прежние версии изменённых файлов из выведенной папки backup, сверяя список `PATCH_BACKUP.json`.
Новые добавленные модули можно оставить: старый код их не использует. Автоматического удаления новых файлов нет.
Рабочий исходный ZIP и dist сохраняются. Музыкальные пути и плейлисты этим патчем не мигрируются.

## Проверки

- Полный unittest: 397 тестов прошли в отдельном Linux-окружении; LibVLC/pywebview в соответствующих тестах заменены doubles.
- Node: 15 проверок фактической логики атрибуции, расположения элемента в HTML и обновления локальных метаданных.
  Это не браузерная отрисовка.
- На сгенерированном звуке проверены MP3, M4A, Opus, Ogg Vorbis, FLAC, WebM и AAC:
  SHA-256 закодированных аудиопакетов до и после работы с метаданными совпали. Для WAV совпали PCM-сэмплы.
- Проверены чтение сведений в новом интерпретаторе, сохранность существующих тегов/файлов,
  коллизии имён, повреждённые/устаревшие companion-записи, повторное применение патча и сохранение локальных правок.
- Проверены синтаксис Python/JavaScript и отсутствие известных шаблонов секретов. Последнее не доказывает отсутствие любых секретов.
- Браузерный Playwright-прогон не выполнен: установленного Chromium нет, скачивание заблокировано сетевым allowlist.

Фактические Linux-зависимости QA записаны в `docs/validation/desktop-fix-a-linux-env.txt`.
Первоначальный TestClient-прогон обнаружил несовместимость старого FastAPI/Starlette с httpx 0.28.1.
Для QA использован FastAPI 0.143.3, версия которого присутствует в METADATA переданного dist.
GUI/provider requirements пользователя не обновлялись. Согласование Windows constraints и свежая Windows-установка — отдельная незавершённая проверка.

## Границы патча и следующий шаг

Обычные отдельные видеоролики пока могут присутствовать в общей YouTube-выдаче: музыкальная категория контента
ещё не подтверждается каталогом. Исправлено превращение контейнеров/каналов/плейлистов в карточки песен.
Страницы исполнителей/альбомов/плейлистов, новый каталог и измеренная оптимизация задержки идут следующим шагом плана.
Ускорение «10 секунд до N» не измерено и не обещается.

Не проверены: Windows/WebView2, фактические источники домашней сети/VPS, конкретная карточка «A4» из живого ответа,
реальные разрешённые скачивания, полнота и версия записей, автономный EXE, backup/restore на ПК владельца.
Основной и независимый резервный путь ещё не выбраны. Продуктового кода бота не добавлено.

`SOURCE_SHA256.json` сохранён как исходный манифест старого этапа; актуальные хеши этого комплекта находятся
в `PATCH_MANIFEST.json` и `SHA256SUMS.json`. Git-ветка `fix/desktop-a` содержит baseline текущего ZIP и отдельный патч.
