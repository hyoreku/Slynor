# Stage17 — отчёт проверки

## Среда

Linux, Python 3.13.14, httpx 0.28.1, FastAPI 0.143.2, Starlette 1.8.0.
Тесты используют LibVLC/pywebview doubles. Windows Python 3.12.2 пользователя
в этой среде не запускался. Нельзя считать Linux-прогон сертификацией Windows.

## Автоматические проверки

- `python -m unittest discover -s tests`: **204 теста, OK**.
- `tools/test_ui.cjs`: **116 assertions**, 1920×1080, 1280×800,
  1000×800, 900×740; без browser JS errors.
- `tools/test_stage16_ui.cjs`: **112 assertions**, OK.
- `tools/test_stage17_ui.cjs`: **119 assertions**, OK; включает предыдущие
  112 проверок и 7 дополнительных, поэтому это не 231 уникальная проверка.
- `python -m pip check`: конфликтов установленных зависимостей не обнаружено.

Дополнительные регрессии: установленный msoc при пустом/некорректном ответе
каталога без живых HTTP/процессов; завершение watchdog/командного потока;
сохранение позиции через заглушку API; безопасные заголовки и Range;
непрозрачный media-handle; запрет частного DNS/внешнего редиректа;
HTTP 403 и HTML вместо аудио; устаревшая ошибка потока; разрыв чтения после
начала ответа; параллельная загрузка одной обложки; отрицательный кеш;
раздельные коды ошибок CDN. Chromium проверяет поздний отказ VLC, единственный
fallback на файл, подтверждение реального playing, остановку без перезапуска
и окончательное завершение при отказе обоих вариантов.

Предупреждение Starlette об httpx остаётся видимым; оно не подавлялось.
Сообщение `possible_ui_stall` в Python-прогоне является ожидаемым результатом
теста диагностического API, а не обнаруженным зависанием приложения.

## Живая сеть (без mocks)

- Реальная обложка публичного видео на i.ytimg.com получена и нормализована
  в JPEG: **35 377 байт**, около **47 мс** в этой среде.
- Реальное разрешение публичного YouTube-аудио через установленный yt-dlp
  завершилось отказом **auth_required**, около **1378 мс**. Источник запросил
  вход/проверку доступа; фактическое аудио не получено.
- Поэтому успешное живое декодирование этого потока через новый прокси и
  воспроизведение его VLC **не подтверждены**. Успешный прокси-путь проверен
  только детерминированными HTTP/API-тестами.

Обложка, доступная здесь, может быть недоступна в пользовательской сети.
По старым событиям `image_unavailable` нельзя установить причину его
5–10-секундных отказов. Новый код даёт более конкретную диагностику, но не
обещает исправить недоступность внешнего CDN.

## Не проверено / не выполнено

- Нативные Windows WebView2/WinForms, libVLC 3.0.24, реальные аудиовыходы.
- Реальное зависание пользователя и его первопричина.
- Успешное скачивание проблемного трека через spotDL/SCDL на компьютере пользователя.
- Windows-сборка EXE, установщик Inno Setup, Authenticode-подпись.

Это архив исходников; ранее добавленные рецепты сборки сохранены,
но собранный или подписанный дистрибутив в него не входит.
