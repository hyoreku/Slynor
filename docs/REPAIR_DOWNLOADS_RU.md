# Ремонт метаданных старых скачиваний

Файлы, скачанные до исправления, могли не иметь длительности и обложки: у WebM/AAC
нет тегов, а sidecar хранил только текст. Инструмент добавляет **только отсутствующие**
измеренные поля и никогда не меняет аудио.

## Запуск

```powershell
python tools/repair_download_metadata.py            # dry run, ничего не пишет
python tools/repair_download_metadata.py --apply    # записать изменения
python tools/repair_download_metadata.py --no-cover # только длительность, без сети
python tools/repair_download_metadata.py --folder <path>
```

По умолчанию папка — `%LOCALAPPDATA%\OwnPlayerMusic\Downloads`.

## Что именно делает

- измеряет длительность файла через PyAV (не доверяет длительности каталога);
- для YouTube-треков скачивает публичное превью `i.ytimg.com/vi/<id>/hqdefault.jpg`
  (только `https`, только этот хост, ≤ 5 МБ, только `image/*`) и кладёт безопасную
  JPEG-копию в `covers/tracks`;
- при `--apply` пишет sidecar атомарно и один раз сохраняет `<sidecar>.bak`;
- пропускает sidecar, если размер/время файла уже не совпадают (устаревшая запись);
- dry run не пишет даже кэш обложек и не ходит в сеть за превью.

## Результат на этой машине

3 sidecar: два SoundCloud-трека уже имели длительность и обложку, один WebM
(YouTube) получил `duration_ms=254361` и обложку. Повторный запуск ничего не меняет.

## Ограничения

- Восстанавливаются обложки только YouTube: в sidecar есть публичная ссылка на видео.
  Для Spotify/SoundCloud обложка без повторного скачивания недоступна.
- Сеть используется через системный прокси Windows (`trust_env`), как у браузера.
- Стерео/теги существующих файлов не мигрируются: это отдельная задача.
