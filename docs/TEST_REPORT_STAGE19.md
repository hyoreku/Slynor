# Slynor, этап 19 — отчёт проверки

## Основа и область изменений

Основа: выданный пользователю архив 18. Изменены название приложения,
источниковый launcher и ряд сценариев стабильности интерфейса/оболочки.
Сеть этапа 18 и пользовательское хранилище не мигрируются.
Сервер для интернет-музыки, новая инфраструктура и зависимости не добавлены.

## Среда и результаты

Linux, Python 3.13, FastAPI 0.143.2, HTTPX 0.28.1 + socksio, Pillow,
NumPy/PyAV; Chromium через Playwright.

- До изменений: **243 Python-теста, OK**.
- После изменений: **253 Python-теста, OK**.
- `tools/test_ui.cjs`: **116 assertions, OK**, размеры 1920×1080,
  1280×800, 1000×800, 900×740.
- `tools/test_stage18_ui.cjs`: **134 assertions, OK** на новой версии до
  последнего небольшого изменения очистки ошибки миниплеера.
- `tools/test_stage19_ui.cjs`: **162 assertions, OK**, включая все 134 проверки
  stage18 и 28 дополнительных; browser JS errors не обнаружены.
- Проверка синтаксиса JS через `node --check`.
- `pip check`: конфликтов в тестовом Python-окружении не обнаружено.

Числа разных UI-наборов не следует суммировать как независимое покрытие.
VLC, Windows-окна, API и нативный мост в тестах подменены doubles/fixtures.
Анимации, DOM, CSS и ожидания ответов исполняются настоящим Chromium.
Проверки не обращаются к реальным музыкальным аккаунтам пользователя.

## Новые сценарии

- Название основного окна, миниплеера, боковой панели, API и имена будущих сборок.
- Сохранён AppId установщика; launcher не выбирает старый EXE вместо исходников.
- Чтение библиотеки, плейлистов и настроек из старой папки без изменения JSON.
- Изменение темы не трогает сетевую конфигурацию и скачанную музыку.
- Нативная оболочка: заголовок миниплеера и сохранение режима окна при скрытии в трей.
- Удаление блокировки `sidebar-resizing` после прерванной анимации.
- Пауза/возобновление цветных пятен на время изменения ширины панели.
- Обновлённые серверные метаданные текущей песни заменяют раннюю неполную запись;
  метаданные с другим путём игнорируются.
- Блокировка паузы при потере связи и восстановление после успешного опроса.
- В миниплеере: доступный Стоп во время открытия, недоступная в этот момент пауза.
- Удержанный старый ответ состояния не отменяет новую команду паузы.
- При задержке метаданных нового трека не остаётся старая обложка.
- После восстановления очищается старая ошибка воспроизведения.

## Ограничения

- Нативное воспроизведение и аудиовыходы Windows/VLC здесь не проверены.
- Не доказано устранение всех зависаний или бесшовная смена скорости на Windows.
- Доступность YouTube/Spotify/SoundCloud через Happ или напрямую не подтверждена.
  Обновление метаданных не делает недоступный сетевой источник доступным.
- Нативная сборка, установщик, SmartScreen и подпись не выполнялись.
- Наличие FFmpeg не доказывает доступ к музыкальному сервису.
- Предупреждение Starlette о httpx в TestClient остаётся предупреждением;
  production-зависимость HTTPX не заменяется вслепую на другой пакет.
- `possible_ui_stall` в тестовом выводе — намеренный вызов диагностического API.

Инструкция приёмки на Windows: `docs/archive/README_STAGE19.md`.
