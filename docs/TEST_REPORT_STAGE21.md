# Этап 21 — результаты проверки

## Среда и границы проверки

Linux, Python 3.13, локальный Chromium/Playwright. Основной UI-набор использует
API и native bridge doubles. Это не Windows/WebView2/VLC и не тест слышимого звука.
Проверка видео отдельно использует настоящий локальный файл и реальный декодер.

## Выполненные проверки

- Python unittest discovery: **257 тестов, OK**.
- Актуальный UI-набор: `tools/test_stage21_ui.cjs`: **234 проверок, OK**. Он включает адаптированные сценарии прошлых этапов; не суммировать
  исторические UI-наборы как независимое покрытие.
- Все frontend JS проходят `node --check`.
- Python compileall backend/player/desktop/check_runtime: OK.
- `pip check` в тестовом окружении: конфликтов нет.

### UI

- Восемь видимых строк с короткими/длинными названиями, отсутствующими
  исполнителями, альбомами, временем и обложками.
- Ширины 1620, 1180, 900 и 540px: фиксированная высота 88/120px, промежуток 8px,
  отсутствие горизонтального переполнения, размещение подписи текущего трека.
- Полное скрытие sidebar на экране песни при обеих исходных ширинах.
  Скрытая панель inert, рабочая область начинается от левого края.
- Возврат сохраняет ручное состояние панели; изменение размера окна не оставляет
  зависший sidebar-resizing. Декоративный фон продолжает движение на паузе.
- Обычный поток вкладок настроек, отсутствие чёрной подложки и широких масок.
- Один оттеняющий слой для обоев, прозрачные поверхности sidebar/workspace/footer.
- Непрозрачный EQ в полупрозрачной теме, полная ширина на экране песни.
- Повторное сохранение визуальных параметров не меняет src видео и не снимает GIF.
- Ручной просмотр снимков библиотеки, настроек, экрана песни и открытого EQ.

### Настоящее видео

`tools/test_stage21_media.cjs` проверен с сгенерированным локальным WebM VP9,
320×180, 30 fps, длительность 1 секунда. Реальное декодирование, три повторных
цикла, отсутствие сброса при повторном событии с тем же URL, остановка/продолжение
при native-window-state и остановка при reduced-motion: **OK**.

В одном записанном прогоне интервалы между последним отображённым кадром
предыдущего цикла и первым следующего составили 67/100/67 мс. Это подтверждает
работу цикла, но **не доказывает нулевой разрыв**. Нативный loop и предзагрузка
не равны гарантированному покадровому бесшовному повтору на любом WebView2.
Исходный файл пользователя не предоставлен, его конечная задержка/кадры/число
повторов не проверялись и не исправлялись.
