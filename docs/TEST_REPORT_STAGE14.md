## Новые проверки

Сохранены проверки очереди/EQ/публичных загрузок/локальной безопасности предыдущих
версий. Добавлены: размеры миниплеера, maximized/fullscreen/normal без безусловного
restore, обычное восстановление минимизированного окна; snapshot метаданных без
чтения файла при опросе состояния; получение и обновление заголовка для того же
пути; отсутствие вертикального переполнения компактного миниплеера.

Браузер проверяет анимации создания плейлиста, фокус после раскрытия, оформление
настоящего custom-popup, управление стрелками/End/Enter/Escape, удаление лишних
блоков и повторного флажка, локальные статусы песни. Сохранены проверки трёх
цветов, свечения, движения/остановки фона, левой панели, очереди, сведений и ⋯.

Проверен интерфейсный путь Spotify-кандидата: подготовка аудио → передача VLC
именно пути готового MP3, а не Spotify-идентификатора. Прослушивание не добавляет
песню в библиотеку без отдельного действия; «+ В список» добавляет и обновляет
статус у песни. Ответы сети и Python-мост в этих UI-проверках подменены.

Проверены URL/обложки известных провайдеров, отказ произвольному URL, последовательный
fallback, повреждённый ответ worker, неверный путь Python загрузчика (поиск не
остаётся running навсегда), ошибка/успешная валидация/кэш загрузки. Успешный
файловый тест использует сгенерированный MP3, не настоящий музыкальный файл.

Адаптеры: spotDL получает providers youtube-music/youtube/soundcloud, bitrate=auto,
один поток; SCDL получает фиксированный URL/папку, --no-playlist, без --sync/--remove;
при отсутствии FFmpeg возвращается ошибка. Сами библиотеки в этих проверках
заменены двойниками. Отмена/тайм-аут убирают worker/попытку завершить дерево,
ожидание pipe ограничено; настоящий taskkill в Windows не проверен.

## Живая сеть и настоящие пакеты

В отдельном Linux-окружении установлены **spotDL 4.5.2**, **SCDL 3.0.8** и их
зависимости. Обе команды версии успешно запущены. Проверка зависимостей показала
наличие FFmpeg. Пакеты не включены в архив приложения.

Успешно получены:

- запрос `Kevin MacLeod` → **12 Spotify-записей**, названия/исполнители/обложки;
- прямая Spotify track-ссылка → правильные название/артист/длительность/обложка;
- запрос `Monkeys Spinning Monkeys Kevin MacLeod` → **12 Spotify-кандидатов**.

Для выбранного совпадения Kevin MacLeod реально вызван spotDL download.
**Загрузка завершилась ошибкой**, файл не получен. stderr библиотеки сообщил
`AudioProviderError: YT-DLP download error`; адаптер вернул понятную ошибку
«spotDL не нашёл доступное аудио для выбранной записи». Из этого нельзя сделать
вывод о конкретной причине (география/сеть/сам провайдер/экстрактор) или о том,
что загрузка обязательно заработает в другой среде.

SCDL запущен командой версии и проверен двойником адаптера, но **настоящая
загрузка SoundCloud через SCDL не выполнена**. Не объявляется успешной.
Успешная живая сетевая проверка Archive из этапа 13 остаётся отдельной проверкой
публичного MP3/Range, не доказательством работы Spotify-загрузки.

## Что не подтверждено

Среда тестирования — Linux + headless Chromium, Python 3.13. VLC, pywebview,
Windows GUI и HTTP в браузерных тестах подменены. Реальное прослушивание,
WinForms/WebView2, DPI, размеры/перетаскивание/полноэкранность на настоящем экране,
скорость обложки из реальной библиотеки, системный трей, длительный прогон,
RAM/CPU/GPU и устойчивость Windows требуют приёмки.

Нет подтверждения, что устранены все зависания, слышимые паузы скорости/EQ;
нет гарантии скачать любой трек, оригинал SoundCloud или получить настоящее
качество 320 kbps из низкобитрейтного источника. Не снимались DRM/подписки,
не использовались cookies браузера или пользовательские токены.
