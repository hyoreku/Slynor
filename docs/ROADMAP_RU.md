# План выпуска Slynor

## 1. Локальный Telegram-бот

Проверить на аккаунте владельца поиск по тексту и ссылке, оригинальный файл и MP3, повторную отправку, ошибки источника и перезапуск загрузки. Для проверки использовать записи, на которые есть право. Сохранить выбранный рабочий источник и известные ограничения в отчёте теста.

Подключение Android и Windows к доставке из бота начнётся с общего контракта `Recording → AudioCandidate → AudioAsset → Delivery`. Приёмка — подтверждение сохранения в библиотеке устройства, повтор без дубликатов и воспроизведение сохранённого файла офлайн.

## 2. Windows x64

1. Запустить Windows CI на коммите-кандидате и пройти [ручную проверку](WINDOWS_ACCEPTANCE.md) в Windows 10 и Windows 11.
2. Собрать `Slynor-Setup.exe` и `Slynor-Portable.zip` по [рецепту](BUILD_PORTABLE_STAGE23.md). Зафиксировать версии и SHA-256 встроенного Python, VLC, FFmpeg и ресурсов провайдеров.
3. На чистой машине проверить оба варианта без системного Python. Пройти запуск, библиотеку, очередь, звук, эквалайзер, мини-плеер, трей, поиск разрешённого файла, установку поверх предыдущей версии и удаление.
4. Снять время старта и p95 обновления библиотеки в WebView2 с 25 000 записей. Проверить масштаб 100% и 150%, тёмную и светлую темы и уменьшенное движение.
5. Опубликовать проверенные Setup, portable ZIP, SHA-256 и заметки о выпуске в GitHub Releases. Для установщика отдельно решить вопрос подписи и SmartScreen.

## 3. Android APK

1. Создать Android-клиент на Kotlin, Jetpack Compose и Media3 по [плану Android](ANDROID_ROADMAP.md). Начать с выбора локальных файлов через Storage Access Framework, библиотеки, очереди и плейлистов.
2. Добавить фоновое воспроизведение через MediaSessionService, media notification, управление с экрана блокировки и Bluetooth.
3. Проверить офлайн-работу, перезапуск, отзыв файловых разрешений, прерывание звука звонком и работу на физическом устройстве. Затем добавить получение файлов из общего сервиса с явным согласием пользователя.
4. Собрать подписанный `Slynor-Android.apk` с воспроизводимым номером версии и SHA-256. Проверить чистую установку и обновление поверх предыдущей версии. Ключ подписи хранить отдельно от репозитория. APK публикуется в GitHub Releases после приёмки Android.

## 4. VPS в РФ

Развёртывание запланировано после приёмки локального бота. Начальная конфигурация — Linux x86_64, 2 vCPU, 4 ГБ RAM и 30 ГБ SSD. На этапе заказа проверить стоимость исходящего трафика и возможность увеличить диск.

1. Подготовить в `/opt/slynor` Docker Compose с контейнерами `music` и `bot`. Зафиксировать версии образов, Python-зависимостей, FFmpeg и выбранного провайдера. Оба контейнера запускаются под непривилегированным пользователем.
2. Запустить `python -m service --host 127.0.0.1 --port 8766 --db /data/service.sqlite3` в `music`. Бот подключается через `network_mode: service:music` и запускается как `python -m telegram_bot --port 8766 --state /bot-data/state.sqlite3`. Compose ждёт успешного `GET /health` с `processing_jobs: true`. Порты наружу не публикуются.
3. Смонтировать отдельно SQLite сервиса, SQLite бота и расходуемые аудиофайлы. Для токена использовать Compose secret, прочитанный процессом при старте. Числовой ID владельца хранить в конфигурации. Включить `restart: unless-stopped`, ротацию логов и уведомление при остатке диска меньше 5 ГБ.
4. Перед переключением остановить локальный long polling. Запустить `docker compose up -d`, проверить `docker compose ps`, затем выполнить из Telegram один поиск и одну доставку разрешённого файла с этого VPS.
5. Настроить ночную резервную копию обеих SQLite через SQLite Backup API, хранение семи копий вне VPS и пробное восстановление в отдельный каталог. После тестовой перезагрузки проверьте возврат сервиса, статус прерванного задания и отправку нового файла. Наблюдать 72 часа за диском, перезапусками и ошибками доставки.
6. Для отката сохранить предыдущие версии образов и резервную копию состояния перед обновлением. При сбое остановить серверного бота, восстановить совместимые образы и, если схема изменилась, соответствующую копию БД. Затем вернуть один экземпляр long polling.
