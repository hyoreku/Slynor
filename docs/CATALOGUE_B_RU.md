# Slynor — каталог B: контракт и исследовательский адаптер

Дата: 27 октября 2026 года. Реализована исследовательская часть итерации B.
Критерии качества источников ещё не приняты. Это исходники, не Windows-релиз.

## Что изменилось

- Общий модуль `backend/catalogue_contract.py`: отдельные track / artist / album / playlist,
  устойчивые provider ID, связи с artist ID, длительность каталога, происхождение обложки и публичная страница.
  Неизвестные поля остаются пустыми. Название и флаг explicit не подтверждают студийную версию или отсутствие цензуры.
- `backend/ytmusic_catalogue.py`: один read-only адаптер для стенда и дальнейшего общего сервиса.
  Поиск песен использует фильтр songs; video/profile/podcast/episode не превращаются в треки.
  В смешанном плейлисте неизвестный тип или музыкальное видео сохраняются отдельной позицией с причиной.
- Исполнитель открывается по выбранному ID. Возвращённый API subscription channelId не заменяет этот ID.
  Первые песни/альбомы обозначаются как top и partial, а не как вся дискография.
- Состав альбома/плейлиста сохраняет порядок, дубли и позиции недоступных записей.
  Лимит 1–100 — видимый бюджет одного исследовательского запроса, не ограничение размера библиотеки.
  Публичный cursor библиотекой не предоставляется; `continuation.mode=not_exposed`.
  Расширение списка с прогрессом и отменой относится к интерфейсной итерации C.
- live/remix/cover/acoustic/remaster/slowed/sped up из названия сохраняются только как подсказки.
  `version_classification=unknown`; обычная карточка не создаёт AudioCandidate/AudioAsset и не разрешает скачивание.
  Явный isPreview сохраняется как preview, остальные случаи — unknown, в том числе запись длиной 30 секунд.
- Ключ будущего кеша различает тип, запрос, язык, регион и маршрут. Новый кеш и ускорение не объявляются реализованными.
- Стенд получил явно выбираемый `ytmusicapi.catalogue`. Старые адаптеры по умолчанию сохранены.
  Хеши общих backend-модулей и lock-файла записываются в manifest для сопоставления сетей.
  Дополнительно измеряются создание адаптера, вызов библиотечного поиска и нормализация.

Новый каталог пока не подключён к обычному GUI. Категории и кликабельные страницы из пятого скриншота — итерация C.
Текущий GUI по-прежнему может показывать отдельные YouTube-видеоролики.
Исходное наблюдение «около 10 секунд» не заменено измерением: baseline на ПК владельца и отрисовка WebView2 не проверены.

## Применение исходников

ZIP содержит чистое дерево `Slynor/`, cumulative manifest и локальную Git-историю.
Патч B включает исправления A и принимает как оригинальный OwnPlayerMusic(2).zip, так и исходники с патчем A.
Помощник проверяет все исходные/новые SHA-256 до записи, сохраняет изменяемые исходники вне проекта
и останавливается при неизвестных локальных изменениях. Повторный запуск пропускает уже установленные файлы.
`APPLY_PATCH_A.py` используется как общий механизм проверок; запускать нужно именно `APPLY_PATCH_B.py`.

Закрыть плеер, проверить резервную копию рабочей сборки и данных по этапу 0.
Распаковать архив отдельно. Открыть PowerShell в распакованной папке `Slynor`:

```powershell
$project = 'D:\Projects\ownwork\OwnPlayerMusic'
$python = Join-Path $project '.venv\Scripts\python.exe'
& $python .\APPLY_PATCH_B.py --project $project --check
& $python .\APPLY_PATCH_B.py --project $project
```

Если Python проекта отсутствует, для помощника подойдёт уже установленный `py -3.13` вместо `& $python`.
Помощник использует стандартную библиотеку, ничего не устанавливает и копирует только исходники.
Музыка, плейлисты, настройки, runtime_paths.json, .venv/.providers/.search и dist в комплект не включены.
EXE не пересобирается. Backup помощника содержит только изменяемые исходники, а не пользовательские данные.
`SOURCE_SHA256.json` и отчёт A сохранены как исторические; актуальные хеши комплекта B находятся
в `PATCH_MANIFEST_B.json` и `SHA256SUMS.json`.
Для отката закрыть плеер и вернуть прежние исходники из выведенной папки backup по PATCH_BACKUP.json;
новые файлы автоматически не удаляются.

## Домашний прогон: только метаданные

При закрытом плеере, с установленным Python 3.13 x64:

```powershell
Set-Location -LiteralPath 'D:\Projects\ownwork\OwnPlayerMusic'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\source_experiment\START_SEARCH.ps1 -Network home_owner -Profile smoke -PrepareCatalogue -Adapters ytmusicapi.catalogue
```

Создаётся только отдельное `.local-artifacts\source-experiment\envs\catalogue`.
Фиксированный hash-lock находится в `requirements-catalogue.txt`; существующее несовместимое окружение сохраняется и требует разбора.
GUI/provider requirements не обновляются. Авторизация, cookies, чужие токены и подписка этому клиенту не передаются.
Используются публичный origin, фиксированные таймауты, отключённые повторы и redirect, лимит тела ответа 2 MiB.
Методы скачивания, изменения плейлистов и произвольные shell-команды в адаптере отсутствуют.

Для сравнения с прежним стендовым ytsearch можно отдельным запуском подготовить и выбрать оба адаптера:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\source_experiment\START_SEARCH.ps1 -Network home_owner -Profile smoke -Prepare -PrepareCatalogue -Adapters yt-dlp.youtube
```

Здесь PrepareCatalogue добавляет новый адаптер к явно указанному yt-dlp; msoc и Archive не включаются.
Это сравнение метаданных стенда, не baseline полного GUI-пути.
После успешного smoke и разбора ошибок выполнить полный набор:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\source_experiment\START_SEARCH.ps1 -Network home_owner -Profile full -Adapters ytmusicapi.catalogue
```

Ручные оценки и независимая доступность заполняются отдельно; успешный HTTP не становится оценкой качества.
Для отчёта нужен только каталог после REPORT_FOLDER, без окружений и аудио.
VPS в РФ должен выполнить тот же набор тем же кодом. Инструкции общего стенда — `docs/experiment/RUN_SEARCH_RU.md` (локально, не публикуется).
Linux Python 3.13 wheels подготовлены, но запуск на VPS не выполнен. Location RU в параметрах каталога не доказывает размещение сервера в РФ.

Для проверки типов и выбранного исполнителя без загрузки аудио:

```powershell
$cataloguePython = Join-Path $project '.local-artifacts\source-experiment\envs\catalogue\Scripts\python.exe'
& $cataloguePython -I .\tools\catalogue_probe.py --operation search --kind artist --query 'Пошлая Молли'
$artistId = Read-Host 'Введите provider_id выбранного исполнителя из выдачи'
& $cataloguePython -I .\tools\catalogue_probe.py --operation artist --id $artistId
```

## Лицензии, зависимости и приёмка

Проверен wheel ytmusicapi 1.12.3 из PyPI, SHA-256
`f65db840907a43ca23b29bd563951a1e390fbe2089d7aa4ddbe2043824b2acd9`.
Его METADATA: MIT, Python >=3.10, единственная обязательная зависимость requests>=2.22.
В lock зафиксированы 7 пакетов, включая монитор psutil; исследовано 10 wheels для Linux 3.12/3.13 и Windows 3.13 x64.
Лицензии по METADATA: ytmusicapi/urllib3/charset-normalizer — MIT, requests — Apache-2.0,
idna/psutil — BSD-3-Clause, certifi — MPL-2.0. Wheels и библиотеки в ZIP не поставляются.
MIT относится к коду клиента и не даёт прав на фонограммы; клиент неофициальный, совместимость с сервисом может меняться.
Для будущего Windows-дистрибутива остаётся проверка notices всех реально поставляемых компонентов.
Аудит файлов и хешей: `docs/experiment/catalogue-wheels-v1.json` (локально, не публикуется).

Проверено: 433 unittest, включая 36 новых; 15 прежних Node-проверок логики UI;
pip check; hash-locked выбор wheels Windows/Linux 3.13 без исполнения на этих платформах;
сохранность исходного набора запросов и отсутствие известных шаблонов секретов.
QA выполнено в отдельном Linux-окружении; фактический freeze — `docs/validation/catalogue-b-linux-env.txt`.
Для полного QA нужны его зависимости; без необязательного requests транспортные тесты пропускаются.
Нативная установка Windows/GUI по старым constraints не считается подтверждённой.

Не проверены: домашняя сеть/VPS РФ, качество и первая полезная карточка, полнота реальных исполнителей/плейлистов,
live/remix/cover в живой выдаче, preview против полного файла, права и разрешённые загрузки,
соответствие spotDL, независимость резервного аудиопути, baseline задержки GUI, WebView2/LibVLC,
Windows-применение помощника, backup/restore на ПК владельца и автономный EXE.

Итерация C подключит этот контракт к поиску и страницам после проверки доступности и качества каталога.
Обязательный эксперимент до бота сохраняется. Продуктовый код бота не добавлен.
