# Stage18 — сеть и прокси: отчёт проверки

## Основа и среда

Исходники извлечены из актуального пользовательского OwnPlayerMusic.zip.
Папки .venv/.providers, кеши, пользовательские логи и музыка не копировались
в итоговый архив. Предыдущие исправления stage17 сохранены.

Среда проверки: Linux, Python 3.13.14, httpx 0.28.1 с socksio,
FastAPI 0.143.2, Starlette 1.8.0, Chromium/Playwright.
Windows пользователя, его VPN и порт прокси удалённо недоступны.

### Новые регрессии

- Системный/ручной/прямой режим; чтение статического прокси; отсутствие
  неявного переключения на прямое подключение при отказе прокси.
- Валидация схемы/порта/URL; запрет встроенного в URL логина/пароля;
  совместимость IPv6 и SOCKS5h.
- Авторизация только в памяти, сохранение без секретов, очистка при смене
  адреса, отсутствие паролей в диагностике и сохранённых настройках.
- Коды проверки фиксированных адресов сервисов; отчёт без URL прокси/секретов.
- SOCKS-DNS через прокси без локального разрешения целевого CDN при сохранении
  списка разрешённых источников; проксирование официальных/импортированных обложек.
- Ограниченный env внешнего процесса, параметры yt-dlp search/stream,
  yt-dlp-args spotDL и SCDL. Не используется ограниченная IPv4/HTTP-only
  настройка `proxy` самого spotDL 4.5.2: requests получает env-маршрут,
  а вложенный yt-dlp получает явно заданный `--proxy`.
- Защита API локальной сессией; отмена заданий и очистка кеша подписанных
  потоков/ошибок обложек при сохранении; сохранность скачанных файлов.
- Экспорт JSON через нативный save-мост (double), отмена диалога, валидация отчёта.
- Chromium: видимость формы только в Technical, переключение режима,
  маскировка пароля, очистка полей, отсутствие секрета в browser storage,
  проверка сохранённого маршрута, выбор приоритета поиска, копирование настоящего
  JSON в clipboard и передача отчёта save-мосту.

## Реальные сетевые соединения на локальном стенде

Это **не MockTransport**:

1. HTTP-клиент отправляет абсолютный URL `http://target.invalid/path`
   локальному тестовому HTTP-прокси; получает ответ стенда.
2. Для HTTPS клиент отправляет CONNECT `target.invalid:443` этому прокси.
   Тестовый сервер специально отвечает 502; подтверждено отсутствие прямой
   повторной попытки. Успешный внешний TLS-туннель этим тестом не проверен.
3. SOCKS5-сервер получает целевое имя `unresolvable.invalid`, а не локально
   разрешённый IP, и передаёт тестовый HTTP-ответ. Проверена proxy-side DNS
   маршрутизация HTTPX, а не доступность какого-либо внешнего музыкального сервиса.

Статус установленного внешнего provider-окружения запускается через новый
worker без httpx в этом окружении: общие worker-helper функции не требуют
добавления httpx к существующей установке spotDL/SCDL. Для requests/SOCKS
нужен PySocks — добавлен в requirements-download.txt и UPDATE_NETWORK.cmd.

## Не подтверждено

- Доступность YouTube/CDN/Spotify/SoundCloud через конкретную VPN пользователя.
- Успешный поиск/поток/скачивание защищённого или недоступного трека.
- Нативный диалог сохранения WebView2 и clipboard-policy Windows.
- Нативные аудиовыходы, реальные зависания и воспроизведение libVLC на Windows.
- Выполнение UPDATE_NETWORK.cmd/INSTALL.ps1 на Windows в этой среде.
- Сборка и Authenticode-подпись EXE/установщика.

Новая версия не отключает проверку TLS и не обходит DRM/авторизацию.
PAC/WPAD и браузерные VPN-расширения автоматически не исполняются.
