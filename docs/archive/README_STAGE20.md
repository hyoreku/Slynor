# Slynor — этап 20: непрерывный фон и полировка интерфейса

Основа: рабочий архив 19. Это обновлённые исходники, не готовая сборка EXE.
Новых зависимостей нет; сервер и аренда хостинга не добавлялись.

## Обновление

1. Выйдите из Slynor через меню трея. Сделайте резервную копию проекта.
2. Распакуйте архив поверх существующего проекта с заменой исходников.
3. Сохраните `.venv`, `.providers` и `%LOCALAPPDATA%\OwnPlayerMusic` без переименования.
4. Запустите `START.cmd`.

## Исправления по изображениям

- Вкладки настроек получили непрозрачную подложку с верхним перекрытием и
  небольшим затуханием снизу. Текст прокрученных секций не просвечивает через
  верхнюю панель, в том числе в полупрозрачной теме и поверх обоев.
- Отступ слева от кнопки запуска песни увеличен до 12px и сохраняется при
  наведении; исправлено и для страницы отдельного плейлиста.
- Движение цветного фона на экране «Сейчас играет» продолжается на паузе.
  Пауза/продолжение песни не создают новую случайную траекторию. Фаза сохраняется
  при скрытии окна и изменении ширины боковой панели.
- Один общий цветной слой охватывает экран песни, левую панель и нижний бар.
  Это один фон, а не три независимо движущиеся копии. Он работает с обоями и без
  них. При выходе с экрана песни возвращается обычное оформление с прежними обоями.
- Убраны разделительные линии между левой панелью, содержимым и нижним баром.
- Убрана декоративная обводка контейнера у всех восьми значков Slynor. Клавиатурная
  рамка фокуса на самой ссылке и обозначение выбранного варианта в настройках сохранены.
- В цветном режиме миниплеера фон также продолжает движение на паузе.

Если песня остановлена кнопкой Стоп и текущая обложка снята, цветной фон может
скрыться вместе с экраном песни. Пауза сохраняет песню и фон.

При скрытом окне анимации приостанавливаются, при возврате продолжаются.
Системная настройка «уменьшение движения» по-прежнему останавливает их — она
не обходится. Спектр остаётся связан с реальным аудио, а не с декоративным фоном.

## Продолжение плана этапа 19

Добавлен `CHECK.cmd` для приёмки текущего окружения Windows. Он не устанавливает
пакеты, не меняет настройки, не скачивает файлы и не воспроизводит аудио.

- Проверяет наличие/версии основных Python-пакетов и наличие FFmpeg.
- В отдельном процессе пробует создать VLC и запросить доступные аудиовыходы;
  ограничение ожидания — 15 секунд. Это не проверка слышимого звука.
- Сохраняет `runtime-check.json` рядом с исходниками (повторный запуск заменяет
  этот диагностический файл). В отчёт не включаются пути, пароли, сетевые адреса
  и названия аудиоустройств.
- Ноль отдельных устройств не объявляется неисправностью: VLC может использовать
  системный выход по умолчанию.

Запускайте `CHECK.cmd` при необходимости, желательно при закрытом плеере.
Отсутствие зависимости отмечается в JSON как null, сбой VLC — native_failed,
превышение ожидания — native_timeout. Результат не доказывает доступ к YouTube.

Подробный лист проверки звука, EQ/скорости, окна, зависаний и будущего установщика:
`docs/WINDOWS_ACCEPTANCE_STAGE20.md`. Здесь доступна автоматическая проверка кода
и Chromium, но нативная Windows-приёмка остаётся отдельной задачей. Подписанного
установщика без реальной сборки и сертификата не заявляем.

Текущий UI-набор: `tools/test_stage20_ui.cjs`. Старые UI-сценарии, ожидающие
остановку декоративного фона на паузе, относятся к прежним версиям.
Отчёт: `docs/TEST_REPORT_STAGE20.md`.
