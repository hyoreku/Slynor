# Slynor: первый пакет оптимизаций — этап 23

**Этот архив содержит обновлённые исходники. Это НЕ готовый portable и НЕ Windows-установщик.**
Старые EXE из пользовательского архива намеренно не включены: они не содержат этих изменений.

## Что изменено

- Поиск Spotify / YouTube / SoundCloud выполняется параллельно, выдача обновляется по готовности источников, а не после самого медленного. Повторные текстовые запросы используют краткоживущий кеш. Ссылки направляются в соответствующий источник.
- Получение потока отделено от очереди скачивания: длинная загрузка не занимает единственный поток подготовки воспроизведения.
- По умолчанию скачивается **доступная исходная аудиодорожка источника**, без обязательного преобразования в MP3. MP3 можно выбрать в разделе интернет-поиска; выбор запоминается. Форматы отдельно учитываются в кеше.
- Для исходного аудио убраны обязательные конвертация, загрузка и встраивание обложки. Это сокращает работу, но теги и обложка в самом скачанном файле не гарантируются. Онлайн-обложки продолжают показываться отдельно.
- Для Spotify используется каталог и сопоставление с доступным аудиоисточником через spotDL. **Это не загрузка оригинального файла Spotify и не гарантия совпадения версии записи.** «Исходное» также не означает lossless или студийный мастер.
- Скачанное проверяется по содержимому, допустимому расширению, размеру и расположению; одна надпись `.mp3` больше не является достаточной проверкой каталожного загрузчика.
- При большой библиотеке создаются только видимые строки с запасом, вместо тысяч элементов одновременно. Фильтрация и очередь используют полный список. Обновление метаданных не должно сбрасывать глубокую прокрутку.
- Очереди более 10 000 треков передаются небольшими порциями, а не одним неограниченным запросом. Лимиты старых API сохранены; добавлены срок жизни, ограничение памяти и проверка порядка порций.
- Исправлено переключение анимации иконок при включении уменьшенного движения.
- Сборка переведена на комплект с собственными Python-runtime, VLC, FFmpeg, Deno и Fixed Version WebView2. Inno Setup только копирует готовый комплект, создаёт ярлык и деинсталлятор; на компьютере пользователя не запускаются установка Python, pip и winget.

## Как пользоваться исходниками

1. Завершить старый плеер через «Выйти». Скопировать в резервную папку исходный проект и `%LOCALAPPDATA%\OwnPlayerMusic`.
2. Распаковать этот комплект в новую папку. Не удалять свою музыку и не заменять рабочую установленную версию непроверенной сборкой.
3. Для запуска **из исходников** по-прежнему нужны Python и зависимости. `INSTALL.ps1` оставлен как инструмент разработчика; это не часть нового установщика.
4. Для самостоятельного Windows-комплекта следовать `docs/BUILD_PORTABLE_STAGE23.md`. Не копировать старую `.venv` в portable и не использовать старый `dist`.
5. После сборки проверить на чистой Windows; затем переносить свои данные. Путь данных сохранён для совместимости.

## Границы результата

- Здесь проверены Python-тесты и интерфейс в Chromium с подменёнными API. Реальные Windows, WebView2, LibVLC, источники музыки и скорость вашей сети ещё требуют проверки. Отчёт: `docs/TEST_REPORT_STAGE23.md`.
- Нет обещания мгновенного поиска: источники могут требовать авторизацию, ограничивать запросы или быть недоступными. Кеш не ускоряет первое обращение к недоступному сервису.
- Библиотека не обрезается до фиксированного числа песен, но память, JSON-хранилище и сортировка остаются конечными. Проверен интерфейс на 25 000 записей, а не «бесконечная библиотека». Для существенно больших коллекций следующий шаг — SQLite/индексы и инкрементальная обработка метаданных.
- Защитный бюджет одной подготовки очереди — 16 МиБ, до двух сессий, 60 секунд простоя; порции до 1 000 путей / 512 КиБ. При превышении выводится ошибка, а не молчаливое обрезание.
- Кеш интернет-поиска — до 64 запросов, 120 секунд; временный каталог — до 1 200 записей. Это не ограничение количества локальных песен. Максимум одного скачиваемого файла сохранён: 200 МиБ.
- Резервные публичные источники могут уже отдавать MP3: «исходное аудио» тогда тоже MP3. Другие поставщики могут не поддерживать конкретную запись.
- Python не устанавливается в систему пользователя, но его приватные файлы остаются внутри приложения. Это нормальная автономная упаковка, а не переписывание программы без Python.
- Аудиофайлы и библиотека по-прежнему сохраняются в `%LOCALAPPDATA%\OwnPlayerMusic`, не возле EXE. Portable означает «распаковал и запустил», а не «все данные внутри одной переносимой папки».
- Сервер, облачное хранение и Android пока не добавлены. Сначала нужна проверенная Windows-версия. Сервер сам по себе не отменит ограничения музыкальных сервисов.
- Загружать следует только записи, для которых у вас есть разрешение/право, с соблюдением правил источника. Личное использование само по себе не гарантирует законность любого скачивания. DRM и ограничения доступа не обходятся.

## Приоритет следующего этапа

1. Получить чистую Windows-сборку и замеры первого/повторного поиска, запуска, импорта и прокрутки на вашем ПК.
2. Если остаются задержки — профилировать чтение метаданных, сохранение JSON и блокировки VLC; затем вводить SQLite и постоянные изолированные воркеры по измерениям.
3. После стабилизации определить контракт синхронизации: идентификатор аудио по хешу, плейлисты, изменения/конфликты, фоновая отправка файлов и удаление. Затем выбирать сервер в РФ и Android-клиент, а не оплачивать сервер заранее.
