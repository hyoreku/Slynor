# OwnPlayerMusic — исправления по логам Windows (stage17)

Это обновление **исходного проекта**, не готовый подписанный установщик.
Зависимости относительно stage16 не изменены. FFmpeg в присланном отчёте уже обнаружен.

## Как применить

1. Полностью закройте OwnPlayerMusic, в том числе через «Выйти» в системном трее.
2. Сохраните копию папки проекта. Для дополнительной страховки скопируйте
   `%LOCALAPPDATA%\OwnPlayerMusic` — там находятся пользовательские данные.
3. Распакуйте архив **в папку проекта**, согласившись заменить исходники.
   Не удаляйте `.venv`, `.providers`, библиотеку, плейлисты и скачанную музыку.
   Архив не содержит личных настроек, токенов, зависимостей или аудиофайлов.
4. В PowerShell из папки проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe start.py
```

Для проверки именно этих исходников используйте вторую команду напрямую:
если рядом остался старый EXE, `START.cmd` может запустить его вместо нового кода.
Подписанный EXE из старой сборки автоматически не обновляется заменой `.py`.

## Что исправлено

- Резервные тесты поиска больше не обращаются к настоящему msoc/SoundCloud
  из-за установленных на компьютере библиотек или настроенных аккаунтов.
  Это исправление тестовой изоляции, не отключение msoc в приложении.
- Тест кеша сравнивает разрешённые пути как `Path`, а не строки с разным
  регистром `C:\Temp` / `c:\temp` на Windows.
- Заглушки DesktopApi реализуют `save_mini_position`; watchdog прерывает
  ожидание при выходе, а простаивающий обработчик команд завершается.
- Для результатов каталога статус «Играет» появляется после подтверждения
  VLC, а не просто после принятия команды очереди. Ожидание ограничено
  15 секундами плюс таймаут текущего запроса состояния до 3 секунд.
- Поздняя ошибка прямого YouTube-потока запускает **одну** резервную попытку
  подготовки локального MP3. Ошибка самого файла отображается, без цикла
  повторов. Остановка или замена уже запускаемого трека отменяет эту попытку.
- Потоки YouTube передаются VLC через локальный непрозрачный media-handle.
  Сохраняются Range и разрешённые заголовки User-Agent/Referer от резолвера.
  Подписанный URL не передаётся в ответе задания. Cookies и Authorization
  не переносятся. Каждый редирект проверяется по CDN и публичному DNS.
- Ошибки получения и чтения потока попадают в состояние текущего трека;
  устаревшая сессия не должна помечать ошибкой новую песню.
- Диагностика обложек различает сетевые таймауты, DNS, соединение, HTTP-код
  и ошибку декодирования. Одновременные запросы одной обложки объединены;
  после отказа действует пауза 15 секунд. При таймауте не выполняется второй
  пятисекундный запрос другого размера к тому же недоступному CDN.

## Что означают присланные логи

- `ffmpeg: true`: приложение уже видит FFmpeg. Его отсутствие не объясняет
  конкретный присланный сбой.
- `StarletteDeprecationWarning`: предупреждение о будущем изменении тестового
  HTTP-клиента, а не провал теста. Основной сетевой клиент приложения — httpx;
  его не следует удалять или заменять на httpx2 ради скрытия предупреждения.
- `device_count: 0`, `enumeration_available: false`: текущий аудиомодуль VLC
  не вернул отдельные устройства. Это **не** доказательство отсутствия
  динамиков в Windows. Системный выход остаётся доступным вариантом.
- Стек с `diagnostic_stacks → dump_stacks` показывает выполнение ручного
  снимка потоков. `queue.get`, `Event.wait`, цикл asyncio и оконный цикл
  сами по себе не доказывают взаимную блокировку. Причина реального зависания
  WebView2/WinForms или VLC по этому снимку не установлена.

## Что проверить на вашем компьютере

1. Запускается ли заведомо рабочий **локальный MP3**, без интернет-поиска?
2. После неудачной загрузки обложки откройте настройки → Технические →
   «Проверить загрузчики и последние ошибки». Сообщите новый `code`
   события `artwork/cover` и `youtube/stream`, без URL, cookies и токенов.
3. Если снова зависнет окно: отметьте действие перед зависанием и продолжался
   ли звук. Автоматический снимок `possible_ui_stall` полезнее снимка после
   нажатия ручной диагностики в уже работающем интерфейсе.

Коды: `image_connect_timeout`, `image_read_timeout`, `image_dns`,
`image_connect_error` (соединение, включая возможный TLS-сбой),
`image_http_403/404/...`, `image_decode_error`, `stream_http_403/...`,
`stream_network`, `stream_read_error`, `auth_required`.

## Ограничения

Обновление не гарантирует доступность любого трека или CDN в конкретной сети.
Права доступа, географические ограничения, авторизация и DRM не обходятся.
Полное воспроизведение внутри приложения используется только для доступного
аудио; превью не подменяет полный трек. Резервный загрузчик тоже может получить
отказ источника, и тогда ошибка остаётся видимой.

Нативное воспроизведение, зависания Windows, перечисление аудиоустройств и
Authenticode-подпись требуют отдельной проверки на Windows. Результаты
проверки этой версии находятся в `docs/TEST_REPORT_STAGE17.md`.
