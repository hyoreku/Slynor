# OwnPlayerMusic — этап 18: сеть и прокси

Это обновление **исходников** из присланного архива. Готового нового EXE и
подписанного установщика здесь нет. `.venv`, `.providers`, логи и личные данные
в исходный архив намеренно не включены — сохраняйте установленные у себя.

## Обновление

1. Полностью закройте приложение через «Выйти» в трее. Сделайте резервную
   копию исходников и `%LOCALAPPDATA%\OwnPlayerMusic`.
2. Распакуйте архив поверх папки проекта с заменой исходников.
   **Не удаляйте `.venv`, `.providers`, скачанную музыку или настройки.**
3. Запустите `UPDATE_NETWORK.cmd`. Он добавляет SOCKS-поддержку, не пересоздаёт
   окружения, не требует смены Python и не переустанавливает VLC/FFmpeg.
   Для загрузки пакетов pip требуется доступ к PyPI; сетевые настройки самого
   плеера на этот отдельный процесс установки не распространяются.
4. Запустите именно обновлённые исходники:

```powershell
.\.venv\Scripts\python.exe start.py
```

Если предпочитаете обновить зависимости вручную:

```powershell
.\.venv\Scripts\python.exe -m pip install "httpx[socks]>=0.28.1,<1"
.\.providers\Scripts\python.exe -m pip install "PySocks>=1.7.1,<2"
```

Если `.providers` отсутствует и загрузчики установлены в основной `.venv`,
вторую команду выполните через `.venv\Scripts\python.exe`.
При собственном `OWNPLAYER_PROVIDER_PYTHON` установите PySocks в указанное
им окружение вручную: CMD не угадывает нестандартные пути загрузчиков.

`START.cmd` при наличии старого EXE может запустить его, а не новые `.py`.
Исходники не обновляют содержимое уже собранного EXE.

## Настройка VPN/прокси

Откройте **Настройки → Технические → Сеть и прокси**.

### 1. Системные настройки

Режим по умолчанию читает `HTTPS_PROXY`, `ALL_PROXY`, `HTTP_PROXY` и статический
прокси Windows через urllib. Приоритет: HTTPS → ALL → HTTP. Для единообразия
он применяется ко всем внешним запросам приложения.

- Если VPN-программа включает системный HTTP-прокси Windows, он может быть
  обнаружен без ручного ввода.
- **PAC/WPAD, автоматический сценарий и расширение VPN в браузере не исполняются.**
  При них нужен явный HTTP/SOCKS-адрес из настроек VPN-программы.
- Если используется полноценный VPN/TUN-туннель для всех программ, он может
  работать и без обнаруженного статического прокси. Сообщение «не найден»
  не означает, что VPN выключен.

### 2. Указать прокси

В VPN-программе найдите раздел с локальным HTTP/SOCKS/Mixed proxy, скопируйте
**адрес, порт и протокол**. Введите их в плеере:

```text
http://127.0.0.1:ВАШ_ПОРТ
socks5://127.0.0.1:ВАШ_ПОРТ
```

Это шаблоны, не готовые адреса: вместо `ВАШ_ПОРТ` нужна реальная цифра из VPN.
Приложение не сканирует порты и не подставляет распространённый порт наугад.
Для HTTP CONNECT-прокси обычно нужен `http://`, даже если открываемый сайт
использует HTTPS. `https://` указывайте только для TLS-соединения с самим прокси.
Поддерживаются также `socks5h://` и IPv6-адреса в квадратных скобках.

Если прокси требует авторизацию, используйте отдельные поля логина/пароля.
Они **не записываются в network.json, localStorage или диагностический отчёт**;
после закрытия приложения потребуется ввести их снова. Не вставляйте пароль
в URL и не присылайте его в чат. Доверяйте только своему прокси: он участвует
в передаче трафика. Проверка сертификатов HTTPS не отключается.

Нажмите **«Сохранить сеть»**, затем **«Проверить доступ»**. Проверяется
**сохранённый** маршрут. После сохранения повторите поиск и запуск песни:
ожидающие задания отменяются, кеш неудачных обложек и подписанных адресов
потоков очищается; скачанные файлы остаются на месте. Уже открытое соединение
может закончить передачу по старому маршруту — для смены остановите и запустите трек.

При отказе настроенного прокси приложение **не переключается тайно на прямое
соединение**. Измените режим сами или исправьте адрес/порт.

### 3. Без явного прокси

Игнорирует HTTP-прокси окружения/Windows для внешних запросов приложения.
Это **не отключает** VPN/TUN на уровне операционной системы.

## Чтобы не ждать лишний каталог

В поле **«Искать сначала»** выберите **YouTube**, если сейчас ищете музыку
именно там. Тогда запрос не будет сначала ждать Spotify. При пустом ответе
остаются резервные каталоги через тот же маршрут.
Автоматический режим сохраняет прежний порядок Spotify → YouTube → SoundCloud.
Это не гарантия мгновенного поиска: сервис, соединение или проверка доступа
могут задерживать запрос и через исправный прокси.

Одинаковый маршрут передаётся HTTP-клиентам обложек/аудио, официальному
SoundCloud, yt-dlp, requests/spotDL, SCDL и необязательным парсерам msoc.
SOCKS использует DNS через прокси; для разрешённых CDN не требуется успешное
локальное DNS-разрешение целевого сайта. Ограничения допустимых источников
сохраняются. Локальные команды плеера не направляются в интернет-прокси.

## Диагностика

Теперь под «Проверить загрузчики и последние ошибки» есть:
- **Копировать отчёт** — с резервным выделением текста для Ctrl+C.
- **Сохранить отчёт** — выбор JSON-файла через диалог Windows.

Сначала можно выполнить «Проверить доступ», затем обновить основной отчёт:
результаты проверки сети включаются в него. Секретные данные прокси и
подписанные адреса потоков в экспорт не добавляются.

Результат `http_200`/редирект подтверждает только HTTP-доступность проверенного
адреса. Он не доказывает доступ к любому треку, исправность всей цепочки
авторизации или фактическое воспроизведение. `proxy_error`, `connect_timeout`,
`http_407` помогают отличать недоступный прокси от ошибки каталога.
Версии загрузчиков содержат `socks_requests` — установлен ли PySocks.

Настройки сети: `%LOCALAPPDATA%\OwnPlayerMusic\network.json`.
Логи: `%LOCALAPPDATA%\OwnPlayerMusic\logs`.
В новых запусках `app.log` помечается `Startup stage18`.

## Ограничения проверки

Маршрутизация проверена на локальных тестовых HTTP/SOCKS5-прокси и doubles
загрузчиков. Доступ через конкретную VPN пользователя, её порт, реальные
потоки YouTube и нативные диалоги/звук Windows в этой среде не подтверждены.
Прокси не снимает авторизацию, DRM или ограничения прав доступа.
Результаты тестов: `docs/TEST_REPORT_STAGE18.md`.
