# Этап 4: встроенные обложки локальных песен и комментарии к коду

## Установка
1. Полностью закрой приложение и останови отдельный сервер, если он запущен.
2. Сделай резервную копию проекта, особенно если самостоятельно менял CSS.
3. Перенеси файлы архива в существующий корень проекта с заменой.
   Не удаляй .venv и данные %LOCALAPPDATA%\OwnPlayerMusic.
4. Новый backend/track_covers.py должен лежать в папке backend.
5. В этом этапе нет новых зависимостей. Mutagen и Pillow нужны как прежде.
6. Из корня проекта запусти:

```bash
./.venv/Scripts/python.exe start.py
```

При сообщении об отсутствующем PIL установи пакет предыдущего этапа:

```bash
./.venv/Scripts/python.exe -m pip install "Pillow>=10.4,<13"
```

## Как проверить
1. Открой «Моя музыка» и дождись загрузки сведений.
2. У песни со встроенной картинкой должна появиться миниатюра.
3. Запусти её — та же картинка появится в нижнем плеере.
4. Запусти песню без картинки — нижний плеер вернётся к заглушке.
5. Открой ⋯ → «Сведения о файле». Поле «Обложка» объясняет её источник
   либо отсутствие. Ошибка чтения обложки не должна портить название/длительность.
6. После изменения тегов файла нажми «Обновить сведения».
7. Проверь воспроизведение, переключение, поиск, громкость и плейлисты.

## Какие обложки читаются
- MP3: ID3 APIC, а также аналогичные ID3-теги в поддерживаемых контейнерах.
- FLAC: блоки pictures.
- M4A/MP4: covr.
- Ogg/Vorbis/Opus: metadata_block_picture или coverart.
Предпочитаем лицевую обложку (type=3). Если она повреждена, пробуем другие.
Встроенные JPG/PNG/WEBP преобразуются в JPEG-копию до 512×512, без увеличения
маленьких картинок. Сохраняются пропорции, на экране используется object-fit.

Не каждый музыкальный файл содержит картинку. Если картинка видна на сайте
или сервисе, это не означает, что она сохранена внутри скачанного MP3.
В этом этапе не ищем изображения в интернете и не читаем соседний cover.jpg.
Воспроизведение файла не зависит от того, удалось ли прочитать его теги.

## Где хранятся копии
%LOCALAPPDATA%\OwnPlayerMusic\covers\tracks

Музыкальные файлы не изменяются. Имя копии — SHA-256 встроенного изображения.
Одна и та же картинка у нескольких песен использует одну JPEG-копию.
Есть ограничения: до 20 МБ изображения и до 40 млн пикселей.
Встроенные картинки с неподдерживаемым форматом дают заглушку.
Метаданные исходного изображения не переносятся в JPEG-копию.

Чтение кэшируется в памяти по пути, размеру и времени изменения аудиофайла.
Перезапуск сбрасывает память, но оставляет JPEG-копии. «Обновить сведения»
сбрасывает кэш чтения и перечитывает теги. Отсутствующая копия восстанавливается
из музыкального файла при следующем чтении метаданных.
Автоматическая очистка неиспользуемых обложек песен пока не реализована.
При необходимости можно удалить только папку covers\tracks, предварительно
закрыв приложение. Не удаляй playlists.json, library.json или covers\playlists.

## Основные места в коде
- backend/track_covers.py: извлечение, проверка картинки, JPEG-кэш.
- backend/metadata.py: объединение текстовых тегов с cover_url/cover_error.
- backend/main.py: маршрут выдачи JPEG-копии и ручное обновление кэша чтения.
- frontend/js/app.js: renderLibrary() создаёт миниатюру строки;
  setSongCover() показывает картинку или заглушку;
  updatePlayerState() меняет обложку в нижнем плеере.
- frontend/index.html: player-cover — контейнер нижней обложки.
- frontend/css/styles.css: раздел 11 — миниатюры и сетка строк.

## Комментарии и изучение
Подробная карта функций: docs/CODE_MAP.md.
- Python: # комментарий
- JavaScript: // комментарий
- CSS: /* комментарий */
- HTML: <!-- комментарий -->
Комментарии поясняют ответственность блока. Не добавляем пояснение к каждой
очевидной строке, иначе код становится труднее читать.

Аудиодвижок, запускатель и хранение плейлистов получили пояснения без изменения
их алгоритмов. Встроенные обложки — отдельная функция чтения и интерфейса.
Следующий этап: реальные настройки цвета и обоев. Интернет-обложки будут
подключены вместе с официальным музыкальным API.
