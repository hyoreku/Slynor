# Slynor Android: реалистичный путь

Статус: проектирование, не готовый APK. Windows-версия продолжает работать отдельно.
Сервер не обязателен для локальной библиотеки и разрешённых прямых загрузок.

## Рекомендация

Для полноценного музыкального приложения — **Kotlin + Jetpack Compose + Media3
ExoPlayer**. Сохранить фирменный знак, цветовые токены, структуру библиотеки,
очереди и плейлистов; нативную оболочку и аудиослой написать для Android.
Media3 Player и MediaSession должны жить в MediaSessionService, отдельно от UI,
чтобы поддержать воспроизведение при заблокированном экране, уведомление и
системные медиакнопки. Учесть foreground-service permissions и тип mediaPlayback.
Источник: https://developer.android.com/media/media3/session/background-playback

Это не «пересобрать EXE в APK»: pywebview Windows, WinForms/WebView2, LibVLC DLL,
pystray, пути дисков и Python subprocess-провайдеры не переносятся как есть.

Вариант WebView/Capacitor позволит использовать часть HTML/CSS, но фоновый звук,
сессия, файловые разрешения и загрузки всё равно потребуют нативного слоя.
Для основного продукта рекомендуем нативный путь; оболочка без Media3 — только
UI-прототип, а не надёжный фоновый плеер. Flutter также возможен, но потребует
отдельной проверки связки плагинов фонового аудио/загрузок и нативных ограничений.

## Что переиспользуем и что меняем

| Компонент | Путь |
| --- | --- |
| Бренд, восемь стилей, палитры | Перенос ресурсов/дизайн-токенов; анимации через Compose |
| Библиотека, очередь, плейлисты | Общая модель записей и стабильные ID; Room на Android |
| Настройки темы/анимаций | DataStore; системное уменьшение анимации и энергосбережение |
| Локальные файлы | content:// URI из системного выбора, не C:\\Music\\... |
| Звук, фоновый режим, блокировка | ExoPlayer + MediaSessionService |
| Трей/отдельное окно миниплеера | Уведомление и компактный плеер внутри приложения |
| Интернет-каталог | Интерфейс провайдера; проверять доступность и право скачивания |
| EQ/скорость | Отдельный этап после стабильной основной сессии; не обещать соответствие VLC один в один |

## Этап 1 — минимальный офлайн-плеер

1. Создать отдельный Android-проект. Выбрать minSdk и targetSdk после проверки
   целевых устройств и актуальных требований распространения, не копировать
   версии SDK/зависимостей из случайного старого примера.
2. Системный выбор нескольких аудиофайлов через Storage Access Framework;
   сохранять выданное persistable URI-разрешение и корректно обрабатывать отзыв
   доступа, перемещение или удаление файла.
3. Библиотека → воспроизведение → очередь → пауза/перемотка/следующий трек.
4. MediaSessionService, media notification, экран блокировки, Bluetooth-наушники,
   audio focus и отключение наушников. UI Activity не владеет плеером.
5. Хранение плейлистов и восстановление после перезапуска процесса.

Приёмка: 30 минут локальной музыки с выключенным экраном; звонок, отключение
наушников, смена приложения, перезапуск процесса и отзыв URI-разрешения.
Не обходить энергополитики или ограничения фонового запуска ОС.

Источник файлового доступа:
https://developer.android.com/training/data-storage/shared/documents-files

## Этап 2 — фирменный UI и экономный живой фон

Перенести дизайн 22: компактные кнопки, стили знака, переключатель экрана песни,
радиальное раскрытие. Три цвета брать из уменьшенной обложки, кешировать по ID.
Анимировать только видимые поверхности; при сворачивании/энергосбережении
отключать декоративный рендер, не само воспроизведение. Проверить TalkBack,
крупный шрифт, контраст и области нажатия; Windows-миниплеер на 112px не копировать
как мобильный экран.

## Этап 3 — интернет и скачивания вместе с развитием Windows

Начать с пользовательских файлов, собственных/лицензированных записей и источника,
который явно предоставляет разрешённый аудиофайл. Наличие ссылки в каталоге
не означает разрешение на скачивание или существование официального API.
Не обещать скачивание Spotify/YouTube/VK по любому URL и не обходить DRM,
платный доступ или проверки авторизации.

Разделить действия «Слушать поток», «Добавить в список» и «Скачать офлайн».
В модели провайдера хранить состояния available / stream-only / downloadable /
blocked / expired, оригинальный источник, устойчивый ID и возможность скачивания.
Служебные signed URL не включать в обычный экспорт, логи и плейлисты как вечные ссылки.

Для разрешённых медиа использовать Media3 DownloadManager + DownloadService:
очередь, состояния, пауза/возобновление, сетевые требования, уведомление и
DownloadIndex. Прогресс опрашивать отдельно: Listener не сообщает каждый процент.
Учитывать актуальные ограничения foreground-service/dataSync выбранной версии
Android; длительную не-медиа синхронизацию проектировать отдельно, не считать
любой бесконечный сервис допустимым. Выходной частичный файл не выдавать за готовый;
проверять тип/размер, ошибки диска, отмену и завершение.

Источник:
https://developer.android.com/media/media3/exoplayer/downloading-media

Проверки: исчезновение сети/места, частичный ответ, повторная загрузка одной записи,
невалидный контент вместо аудио, истёкшая ссылка, отмена, перезапуск и офлайн-режим.
Загрузчики Windows в этом архиве не переписаны под Android и не получили обещания
новых музыкальных источников.

## Этап 4 — обмен библиотекой

Сначала добавить явный экспорт/импорт переносимой схемы: UUID треков, метаданные,
плейлисты, настройки и локальные ссылки на обложки. Windows-пути сопоставлять с
новыми Android URI после выбора файлов пользователем, а не переносить буквально.
Аудиофайлы копируются с разрешения пользователя. Облако и постоянный backend —
только отдельное решение, не обязательная первая зависимость.

## Следующий конкретный шаг

После Windows-приёмки 22 — отдельный Android MVP: выбор локального трека,
воспроизведение через Media3 и управление из уведомления при выключенном экране.
Только после его проверки подключать каталог, загрузки, EQ и межустройственный обмен.
Срок и стоимость без набора целевых устройств и объёма источников не оцениваются.
