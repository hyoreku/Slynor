## Новые Python-сценарии

- Выдача готового результата до завершения медленного параллельного источника.
- Попадание/истечение кеша, изменение сетевого предпочтения, повторная регистрация записей из кеша, маршрутизация прямой ссылки.
- Отмена и удалённое задание; отдельный executor получения потока.
- Исходный формат и MP3, отдельные ключи кеша, сохранение индекса, проверка испорченного содержимого; Spotify URL matching без преобразования оригинала; SoundCloud/YouTube исходное аудио без postprocessor.
- Существующие ограничения Pydantic оставлены; сборка длинной очереди, порядок, TTL, бюджет памяти, ограничения числа сессий/размера порции.
- Реальные HTTP-вызовы локального ASGI через TestClient для chunk API: авторизация, Origin, ошибка 1001 пути в порции, неполный commit, отмена, последовательность 10 001 пути, shuffle и невозможность повторного commit.
- Приватный путь интерпретатора, bundled native paths при frozen-старте, безопасное извлечение embeddable ZIP, структура установщика без pip/winget/Python-install.
- Аудиопроверка не делает автоматическое распознавание произвольного плейлиста: задан контейнер и разрешены только локальные протоколы.

В старых тестах обязательный MP3 стал **явно выбранным** MP3: соответствующие фикстуры теперь передают `audio_format='mp3'`, сохраняя проверки поведения. Контракт packaging обновлён под новый автономный установщик вместо старого online-bootstrap. Утверждения не удалялись ради получения зелёного результата.

## Что эти результаты НЕ доказывают

- Не измерены секунды реального поиска/скачивания: провайдеры подменены, зависимость от сети и блокировок остаётся.
- UI-набор на 25 000 записей использует подготовленные метаданные. Он не доказывает скорость импорта, чтения тегов, записи JSON, использование памяти или FPS при сканировании реальных 25 000 файлов.
- Не выполнены live-запросы Spotify/YouTube/SoundCloud. Работа конкретных библиотек, доступность треков, точность совпадения и зависимости на Windows нуждаются в практической проверке.
- Новый PowerShell-сценарий не запускался; прежний файл `docs/validation/powershell-syntax.txt` относится к более раннему комплекту, не к этому выпуску.
- Private embedded Python, Deno, Fixed WebView2, VLC и FFmpeg не поставлены бинарно в этом архиве. Совместимость wheels/нативных redistributable, чистая Windows без Python, реальный звук и установщик — обязательный следующий этап.
- Логи тестов содержат предупреждение библиотеки Starlette о будущей смене TestClient transport и искусственный `possible_ui_stall` из тестовой фикстуры; итоговый unittest завершился `OK`. Это не отчёт о наблюдавшемся зависании реального приложения.

## Повторение

Из корня проекта в окружении разработчика с зависимостями:

```text
python -m unittest discover -s tests
node tools/test_stage22_ui.cjs
node tools/test_stage23_ui.cjs
node tools/test_stage22_layout.cjs
```

Для JS нужен пакет Playwright и совместимый Chromium. При необходимости `CHROMIUM_PATH` задаёт путь к браузеру. Пример Linux: `CHROMIUM_PATH=$(command -v chromium) node tools/test_stage23_ui.cjs`.
В репозиторий не включены node_modules и тестовые venv. Логи этого прогона — `docs/validation/stage23-*`.

Windows-приёмка и сборка: `BUILD_PORTABLE_STAGE23.md`. Приложение пока следует считать кандидатом на проверку, а не подтверждённым Windows-релизом.
