# Music Service, этап 1: проверка на Windows

Дата: 2026-10-28. Машина владельца, Windows, Python 3.13 x64 из `.venv`,
изолированный обработчик `.providers` (yt-dlp 2026.8.19), системный прокси
`127.0.0.1:10809`. Проверялся вертикальный срез «поиск → кандидат → скачивание →
доставка» в реальном процессе `python -m service`, а не только на двойниках.

## Что запускалось

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe tools\stage0_audit.py
.\.venv\Scripts\python.exe -m service --db .local-artifacts\service-smoke.sqlite3 --port 8776 --proxy http://127.0.0.1:10809
```

Клиент — httpx с `trust_env=False` (иначе системный прокси ломает loopback-запросы).
Служебная база, скачанный файл, `assets/`, `work/` и `outbox/` после проверки удалены;
в репозиторий ничего из этого не попало.

## Результаты

| Проверка | Результат |
|---|---|
| Полный набор тестов | `Ran 521 tests`, `OK (skipped=12)` |
| Аудит состава | `no_pattern_findings`, 330+ кандидатов, ручной просмотр diff по-прежнему нужен |
| `GET /health` | `status=ok`, `schema_version=1`, `journal_mode=wal`, `dispatcher=true` |
| Задание `search` | `done`, `attempts=1`, 2,9 с; 3 элемента при `limit=3`, устойчивые 11-символьные ID |
| `GET /providers` | youtube — search/download/resolve; spotify и soundcloud — search/download |
| Повторный поиск | существующие `Recording` и `AudioCandidate` переиспользованы, дублей нет |
| `resolve` | хост оканчивается на `*.googlevideo.com`; из заголовков сохранён только User-Agent |
| Задание `download` | `done`, `attempts=1`; webm/opus, 3 166 041 байт, SHA-256 `b62e2485…c28b53` |
| Измерение длительности | 205 221 мс по файлу против 206 000 мс в каталоге |
| Задание `deliver` | `sent`, `external_ref=telegram_smoke-4982879a.webm`, боковой `*.delivery.json` есть |
| Повторная доставка | возвращает ту же запись, файл не отправляется второй раз |
| Синтетические контейнеры | mp3 1200 мс, webm/opus 1208 мс — измерено PyAV, чужого аудио нет |

Наблюдение по выдаче: при запросе «Пошлая Молли» две из трёх строк оказались
длинными сборниками («плейлист …», 26–27 минут) и стояли выше отдельной песни.
Сервис такие строки не отбрасывает и не переставляет: правила качества и
версий должен дать обязательный эксперимент источников (ТЗ §4). Это не регрессия,
а известное ограничение среза.

## Что этим не доказано

- Релевантность и полнота выдачи, выбор основного и резервного аудиоисточника.
- Работа с домашней сети против VPS в РФ, а также лицензии конкретных записей.
- Telegram-доставка, `file_id`-кеш, TTL и очистка кеша — кода бота ещё нет.
- Windows GUI/WebView2/LibVLC, установщик, чистая VM.
- Две параллельные загрузки: диспетчер один, реально выполнялась одна.
- Восстановление заданий под нагрузкой и длительная работа сервиса.
