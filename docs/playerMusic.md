## 1. Общее описание

**Slynor** (ранее OwnPlayerMusic) — десктопное приложение для Windows, объединяющее:

- **Онлайн-поиск и стриминг** музыки из открытых источников (SoundCloud, Jamendo, Audiomack, Internet Archive).
- **Локальную библиотеку** (mp3, flac, wav, ogg, m4a, aac).
- **Опциональное скачивание** треков для офлайн-прослушивания.

**Для кого:** пользователи, которые хотят бесплатный плеер с поиском по мировому каталогу, но при этом ценят приватность (все данные хранятся локально).

---

## 2. Ключевые принципы

| Принцип | Значение |
|---------|----------|
| **Локальность** | Все данные (БД, настройки, музыка) хранятся на компьютере пользователя |
| **Приватность** | Никакой телеметрии, шифрование чувствительных полей |
| **Бесплатность** | Пользователь не платит за прослушивание |
| **Расширяемость** | Плагины для новых источников и эффектов |
| **Синхронизация** | REST + WebSocket API для связи с Ассистентом (второе приложение) |

## 3. Источники музыки и API

### 3.1. SoundCloud API

**Что даёт:**
- Полноценный текстовый поиск по названию трека или автору.
- Метаданные: название, исполнитель, обложка (`artwork_url`), длительность.
- Прямой URL аудиопотока (`stream_url`) для кастомного плеера.

**Качество:** MP3 128 kbps или Opus 64 kbps (бесплатный API).

**Аутентификация:** OAuth 2.0. Для публичного доступа достаточно Client Credentials.

**Ограничения:**
- Не все треки стримабельны: проверяй поле `access` (`playable`, `preview`, `blocked`).
- Rate limit: **15 000 запросов в 24 часа** на `client_id`.
- Для стриминга через кастомный плеер **обязательна атрибуция**: указать загрузившего как автора, указать SoundCloud как источник, дать ссылку на оригинальный трек.

**Как получить доступ:** регистрация приложения на `developers.soundcloud.com`. SoundCloud также публикует OpenAPI spec на GitHub и LLM Context для AI-ассистентов.

---

### 3.2. Jamendo API

**Что даёт:**
- Огромная библиотека независимой музыки под лицензиями **Creative Commons**.
- **Официальное бесплатное скачивание** треков в MP3 320 kbps.
- Поиск по тегам, автору, названию.
- API возвращает прямую ссылку на скачивание (`audio`), обложку (`image`), имя исполнителя (`artist_name`).

**Качество:** MP3 320 kbps, OGG, FLAC (через `audioformat` параметр).

**Аутентификация:** только `client_id` (без OAuth для публичного поиска).

**Как получить доступ:** регистрация на `devportal.jamendo.com`.

**Особенность:** поле `audiodownload_allowed` показывает, разрешил ли автор скачивание.

---

### 3.3. Audiomack API

**Что даёт:**
- Стриминг и загрузка в MP3 до 320 kbps.
- Поиск треков, альбомов, артистов.
- Структурированные JSON-данные: метаданные, обложки высокого разрешения, ссылки на аудиопоток.

**Качество:** MP3 до 320 kbps.

**Аутентификация:** OAuth 1.0a (three-legged) для пользовательских действий; опционально `key` параметр для read-only доступа.

**Как получить доступ:** запрос через страницу для разработчиков `audiomack.com/data-api/docs`.

**Специализация:** хип-хоп, электронная, независимая музыка. Сильное присутствие в Африке, Карибах, США.

---

### 3.4. Internet Archive API

**Что даёт:**
- Миллионы легальных аудиозаписей: живые концерты (Live Music Archive), старые пластинки, аудиокниги.
- **Высокое качество: FLAC, Lossless WAV** — абсолютно бесплатно.
- Advanced Search API для поисковых запросов.
- Метаданные, ссылки на изображения, список файлов внутри архива.

**Аутентификация:** не требуется для поиска и скачивания публичных файлов.

**Как получить доступ:** документация на `archive.org/developers`.

**Особенность:** нужно **парсить списки файлов** внутри архива, чтобы вытянуть прямые ссылки на `.flac` или `.mp3`.

---

### 3.5. Гибридный подход (рекомендация)

**Проблема:** SoundCloud даёт стриминг, но не даёт скачивания. Jamendo даёт скачивание, но каталог ограничен инди-музыкой. Internet Archive даёт FLAC, но требует парсинга.

**Решение:** использовать **несколько источников одновременно**.

**Схема работы:**

1. **Поиск:** пользователь вводит название трека.
2. **Параллельный запрос** к SoundCloud API (стриминг) + Jamendo API (скачивание) + Internet Archive (FLAC).
3. **Результаты объединяются** в единый список с индикатором источника.
4. **При выборе трека:**
   - Если пользователь хочет **слушать** → берём `stream_url` из SoundCloud (или Jamendo `audio`).
   - Если пользователь хочет **скачать** → берём `audio` из Jamendo (если `audiodownload_allowed`) или файл из Internet Archive.
   - Если трек недоступен нигде → показываем сообщение.

**Для поиска по «мировым звёздам» (Linkin Park, Radiohead):**
- Использовать **MusicBrainz API + Last.fm API** для получения метаданных (название, исполнитель, обложка).
- Затем искать этот трек в SoundCloud/Jamendo по точному совпадению названия и автора.

## 7. Схема базы данных

```sql
-- Настройки (зашифрованы через pgcrypto)
CREATE TABLE settings (
    key TEXT PRIMARY KEY,
    value_enc BYTEA,
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Треки
CREATE TABLE tracks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title TEXT NOT NULL,
    artist TEXT,
    album TEXT,
    duration_sec INTEGER,
    file_path TEXT UNIQUE,          -- NULL для онлайн-треков
    file_hash TEXT,
    cover_path TEXT,
    bitrate INTEGER,
    format TEXT,
    source_type TEXT NOT NULL,      -- 'local' | 'soundcloud_stream' | 'jamendo_download' | 'archive_download'
    stream_url TEXT,                -- временный для онлайн
    external_id TEXT,               -- ID в источнике (SoundCloud track ID, Jamendo ID)
    external_url TEXT,              -- ссылка на источник
    added_at TIMESTAMPTZ DEFAULT NOW()
);

-- Плейлисты
CREATE TABLE playlists (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name TEXT NOT NULL,
    description_enc BYTEA,
    cover_path TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Связь плейлист-трек
CREATE TABLE playlist_tracks (
    playlist_id UUID REFERENCES playlists(id) ON DELETE CASCADE,
    track_id UUID REFERENCES tracks(id) ON DELETE CASCADE,
    position INTEGER NOT NULL,
    added_at TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (playlist_id, track_id)
);

-- История (чистится раз в месяц)
CREATE TABLE play_history (
    id BIGSERIAL PRIMARY KEY,
    track_id UUID REFERENCES tracks(id) ON DELETE SET NULL,
    played_at TIMESTAMPTZ DEFAULT NOW(),
    duration_played_sec INTEGER,
    completed BOOLEAN DEFAULT FALSE
);

-- Очередь shuffle (сбрасывается при закрытии)
CREATE TABLE shuffle_queue (
    id SERIAL PRIMARY KEY,
    playlist_id UUID REFERENCES playlists(id) ON DELETE CASCADE,
    track_id UUID REFERENCES tracks(id) ON DELETE CASCADE,
    position INTEGER NOT NULL
);

-- Кэш поиска
CREATE TABLE search_cache (
    id SERIAL PRIMARY KEY,
    query TEXT NOT NULL,
    source TEXT NOT NULL,           -- 'soundcloud' | 'jamendo' | 'audiomack' | 'archive'
    result_json JSONB,
    cached_at TIMESTAMPTZ DEFAULT NOW()
);

-- Логи скачивания
CREATE TABLE download_logs (
    id BIGSERIAL PRIMARY KEY,
    source TEXT NOT NULL,
    query TEXT,
    status TEXT NOT NULL,           -- 'success' | 'failed' | 'in_progress'
    file_path TEXT,
    started_at TIMESTAMPTZ DEFAULT NOW(),
    finished_at TIMESTAMPTZ
);
```

**Шифрование:** поля с `_enc` шифруются через pgcrypto (`pgp_sym_encrypt`/`pgp_sym_decrypt`). Ключ хранится в **Windows Credential Manager** через библиотеку `keyring`.

## 11. Согласованный интерфейс и кастомизация — актуальное дополнение

### Текущие решения

- Интерфейс вдохновлён компоновкой Meridius, но реализуется самостоятельно.
- Основной акцент по умолчанию — фиолетовый.
- При запуске открывается «Главная» с карточками плейлистов.
- Слева — навигация и плейлисты, по центру — отдельный прокручиваемый экран.
- Снизу — постоянный плеер: текущая песня, воспроизведение/пауза, переключение,
  перемотка, shuffle и громкость без кнопки применения.
- Очередь открывается справа по отдельной кнопке.
- HTML, CSS и JavaScript разделены. На текущем этапе используются обычные
  HTML/CSS/JavaScript; переход на React не является обязательным для этого этапа.
- Пользователь хочет самостоятельно участвовать в оформлении. Изменения
  интерфейса объясняются небольшими шагами с указанием файлов и CSS-свойств.

### Обязательные функции кастомизации

1. Цветовая гамма в настройках:
   - выбор акцентного цвета;
   - светлая и тёмная тема;
   - сохранение между запусками;
   - сброс к исходному фиолетовому оформлению;
   - читаемость текста и элементов на выбранном фоне.
2. Обои приложения:
   - выбор собственного локального изображения;
   - настройка отображения фона (масштабирование, затемнение, при необходимости размытие);
   - сохранение выбора и возможность убрать обои;
   - импорт копии в папку данных приложения, чтобы перенос исходника не ломал оформление.
3. Свои изображения плейлистов:
   - выбор локальной картинки для каждого плейлиста;
   - квадратное отображение/кадрирование без изменения исходника;
   - сохранение независимо от переименования плейлиста;
   - возможность заменить или удалить пользовательскую обложку;
   - резервная стандартная обложка при отсутствии картинки.

### Порядок ближайших этапов

1. Каркас интерфейса: главная, навигация, нижний плеер, просмотр очереди — подготовлено.
2. Музыкальный список: компактные строки, столбцы, обложки треков, меню действий.
3. Плейлисты: экран подборки, свои изображения, удобное создание и редактирование.
4. Настройки: цветовая гамма, светлая/тёмная тема, обои, сохранение персонализации.
5. Эквалайзер, пресеты и выбор устройства вывода.
6. Онлайн-поиск и воспроизведение через официальные API с проверкой доступа,
   актуальных условий сервиса и разрешений на скачивание.
7. Остальные этапы исходного ТЗ: визуализация, интеграции, безопасность,
   упаковка, установщик, тестирование на Windows 10 и Windows 11.

### Что ещё не реализовано

Настройки цветовой гаммы, обои и собственные изображения плейлистов пока
запланированы. Страница «Настройки» показывает это явно, без неработающих
переключателей. Фиолетовые заглушки обложек — временное оформление.
Список треков на первом UI-этапе сохраняет прежние кнопки действий; таблица
и контекстное меню появятся отдельно. Просмотр очереди пока не поддерживает
перетаскивание или выбор трека внутри панели.
