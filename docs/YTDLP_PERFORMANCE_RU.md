# Скорость yt-dlp: замеры 2026-10-28

Цель — понять, можно ли быстрее запускать онлайн-треки YouTube. Замеры на этой машине,
извлечение `bestaudio[protocol=https][ext=m4a]/bestaudio[protocol=https]` для
`https://www.youtube.com/watch?v=I-esFAcafYo`, `.providers` окружение, yt-dlp 2026.08.19.

| Вариант | Время | Результат |
|---|---:|---|
| напрямую | 2,82 с | m4a, 129 kbps |
| через системный прокси `127.0.0.1:10809` | 2,28 с | m4a, 129 kbps |
| Deno 2.9.8 + `yt-dlp-ejs` | 3,27–3,70 с | m4a; предупреждение о JS-рантайме исчезает |
| `player_client=android` | — | формат `https/m4a` не предлагается |
| `ios`, `tv`, `mweb`, `web_safari`, `android_vr` | — | формата нет / ошибка клиента |

## Выводы

1. **Альтернативные клиенты YouTube не ускоряют**: нужного `https/m4a` у них нет,
   а формат менять нельзя без потери совместимости.
2. **Deno не ускоряет** извлечение (даже чуть медленнее), но без JS-рантайма yt-dlp
   предупреждает, что часть форматов может отсутствовать. Deno нужен для полноты
   и надёжности, а не для скорости. При установке в PATH (`winget install DenoLand.Deno`)
   yt-dlp находит его сам; для исходников этого достаточно.
3. **Главный выигрыш — кеш разрешённого потока.** Ссылки `googlevideo` живут часами,
   поэтому кеш в `CatalogueLibrary` увеличен с 5 до 30 минут: повторный запуск трека
   в сессии больше не платит 2–3 секунды за новое извлечение.
4. **Скачивание**: формат `original` не конвертируется (быстро), `MP3` добавляет
   время FFmpeg — это осознанный выбор пользователя в интерфейсе.
5. Поиск использует `extract_flat` и уже ограничен 8–12 результатами на источник —
   отдельного ускорения здесь не требуется.

## Что можно сделать дальше

- Предзагрузка следующего трека очереди (старт извлечения заранее) — даст ощутимый
  выигрыш при непрерывном прослушивании, но требует аккуратной отмены и бюджета.
- Персистентный кеш разрешённых URL между запусками не рекомендуется: ссылки истекают.
