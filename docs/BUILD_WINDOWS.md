# Подготовка Windows-дистрибутива и подписи

В этом архиве **нет готового подписанного EXE/установщика**. Исправленный рецепт и проверочный сценарий подготовлены, но не выполнялись на Windows. Актуальные шаги: `README_REBUILD_RU.md` в корне проекта. Нужны нативная сборка и приёмка; нельзя считать исходный скрипт проверенным дистрибутивом.

## Сборка

На Windows x64:
1. Запустите INSTALL.ps1 из исходников; проверьте запуск приложения.
2. Установите Inno Setup 6 с официального сайта https://jrsoftware.org/isinfo.php (нужен ISCC.exe).
3. Выполните `powershell -NoProfile -ExecutionPolicy Bypass -File .\BUILD_WINDOWS.ps1`.
4. Результат: `dist\Slynor\` (PyInstaller onedir) и `dist\installer\Slynor-Setup.exe` (Inno Setup). **Без сертификата это неподписанная сборка**, скрипт об этом предупреждает.

Worker-процессы запускаются только отдельным Python из `.providers` / `.search`, а не GUI-EXE. Входной скрипт поддерживает `--check-runtime` и `--smoke-test` без открытия GUI. Обычный путь загрузчиков — установленное отдельное окружение `.providers` рядом с EXE. `backend/provider_worker.py` и msoc_worker.py включаются как ресурсы для запуска внешним Python. Frontend — внутри `_internal/frontend`. Путь ffmpeg берётся из runtime_paths.json рядом с EXE, настройки/музыка остаются в LOCALAPPDATA\OwnPlayerMusic.

Установщик ставит файлы в пользовательскую папку LocalAppData\Programs\Slynor, не удаляет личную библиотеку. В интерактивном режиме выполняет INSTALL.ps1 с видимым окном и ждёт кода завершения. При ошибке **не запускает плеер автоматически**. Это онлайн-bootstrap: требует сети/winget и может показать запросы сторонних установщиков. Не является автономным офлайн-пакетом. Тихая установка не запускает зависимости автоматически.

## Значок приложения и трей

BUILD_WINDOWS.ps1 перед упаковкой запускает `tools/build_app_icon.py` и создаёт
многоразмерный app.ico из `frontend/assets/logo.png`. Он встраивается в EXE.
`frontend/assets/icons/tray.png` используется отдельно и не перезаписывается
генератором. Замена исходников не меняет значок уже собранного EXE.

## Настоящая подпись

Нужен действующий сертификат **Code Signing** с приватным ключом в личном хранилище пользователя Windows (`Cert:\CurrentUser\My`) либо отдельный сервис подписи. Закрытый ключ/PFX и пароль не отправляйте в чат. Для аппаратного токена/облачного HSM нужен отдельный процесс провайдера; текущий скрипт ориентирован на сертификат, доступный signtool в Windows.

1. Установите Windows SDK Signing Tools (signtool.exe).
2. Укажите публичный отпечаток своего сертификата:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\BUILD_WINDOWS.ps1 -SignThumbprint 'ОТПЕЧАТОК_40_HEX'
```

Скрипт проверяет срок, наличие приватного ключа, EKU Code Signing; подписывает приложение **до упаковки**, затем установщик. SHA-256, RFC3161 timestamp, `signtool verify /pa` и Get-AuthenticodeSignature. При неуспешной проверке останавливается. Самоподписанный сертификат не предлагается как замена доверенной публичной подписи; подпись не гарантирует отсутствие предупреждения SmartScreen у нового приложения.

## Обязательная приёмка до распространения

- Чистая Windows 10/11 x64: установка, первый запуск, VLC, WebView2, ffmpeg/ffprobe, отсутствие второго GUI при поиске/загрузке.
- Перезапуск: `.providers` найдено; загрузчики не используют EXE как обычный Python случайно; кэш и данные сохранены.
- Реальный звук/устройства, трей, миниплеер, high DPI/fullscreen и сценарий зависания.
- Проверка подписи на другом ПК с доверенной цепочкой, временной меткой и доступом к проверке отзыва.
- Удаление приложения не удаляет LOCALAPPDATA\OwnPlayerMusic с музыкой и плейлистами. Повторное обновление не переносит пользовательские данные из папки исходников.
- Юридическая проверка лицензий и уведомлений Python/Qt или WebView2/LibVLC/FFmpeg и остальных включаемых компонентов перед распространением. Текущий рецепт не заменяет такой аудит.
